# 专利初稿：一种面向区块生产者的动态评分与探索利用自适应机制、系统、装置及存储介质

## 1. 摘要

本发明公开了一种面向区块生产者的动态评分与探索利用自适应机制、系统、装置及存储介质。该机制基于区块生产者的行为观测数据，计算对应的动态评分和 reward 学习结果；其中，所述行为观测数据至少包括服务成功率、失败率、异常行为次数、正向行为次数和价值产出信息。进一步地，基于动态评分和 reward 学习结果构造区块生产者的预期收益指标或健康度指标，并结合 exploration / exploitation 分层机制，对样本不足或新加入的区块生产者进行探索评估，对样本充分的区块生产者进行利用评估，从而输出面向区块生产者的排序、筛选、准入、健康评估或调度结果。该方案能够抑制存在高风险行为的区块生产者长期获得优势地位，提升高质量区块生产者的识别精度，并缓解系统长期依赖少数既有区块生产者造成的中心化问题，从而提升区块生产者管理机制的风险控制能力、稳定性和适应性。

## 2. 技术领域

本发明涉及区块链交易处理、区块构建、智能调度和系统健康评估技术领域，尤其涉及一种面向区块生产者的动态评分、reward 学习以及 exploration / exploitation 自适应机制的方法、系统、装置及存储介质。

## 3. 背景技术

当前已经存在一些区块链相关的订单流共享、提示传播或返还机制，例如 mev-share 一类方案。该类方案通常更关注交易信息的共享方式、暴露粒度和交互路径，而对于底层参与服务的 builder 或 block producer，往往缺少一套独立、可持续学习、可用于长期管理的评价与调度机制。

在现有技术中，对于区块生产者的处理方式通常较为粗粒度，常见做法是依赖静态名单、人工经验配置、固定权重、短期成功率或简单可用性检查来进行选择。这种方式在实际运行中至少存在以下问题：

1. 缺乏面向区块生产者的长期动态评价机制，难以持续刻画不同区块生产者的服务质量、稳定性和行为风险；
2. 缺乏对异常行为或高风险行为的持续惩罚机制，例如难以及时识别并压制具有 sandwich attack 倾向、失效率升高或存在不良行为模式的区块生产者；
3. 仅依赖静态权重或短期表现，无法同时反映区块生产者的长期信誉和近期状态变化，容易导致评价结果失真；
4. 对于新加入或样本不足的区块生产者，现有方案通常缺少探索性评估机制，导致系统难以发现潜在高质量区块生产者，进而加剧中心化；
5. 现有方案通常将区块生产者选择附着在具体业务链路上，例如订单流分发，而没有抽象出一套可独立复用的底层机制，因此难以扩展到健康评估、准入控制、资源调度或策略路由等其他场景。

因此，需要一种面向区块生产者本身的独立技术机制，用于对区块生产者进行动态评分、reward 学习和探索利用控制，从而支持更稳定、更可解释且更具适应性的区块生产者管理。

## 4. 发明内容

### 4.1 发明目的

本发明的目的在于提供一种面向区块生产者的动态评分与探索利用自适应机制，通过构建基于行为画像的区块生产者动态评分机制、基于 reward 的收益学习机制，以及基于 exploration / exploitation 的分层机制，实现以下目标：

1. 对区块生产者进行持续的、可在线更新的长期信誉评估；
2. 利用近期 reward 学习结果反映区块生产者的短期状态和收益质量变化；
3. 通过 exploration / exploitation 机制解决新加入区块生产者的冷启动问题，并降低长期中心化风险；
4. 输出可用于健康评估、准入控制、资源调度、策略排序或业务选择的统一指标结果。

### 4.2 技术方案

为实现上述目的，本发明提供一种面向区块生产者的动态评分与探索利用自适应方法，包括：

1. 获取多个区块生产者的行为观测数据；
2. 基于所述行为观测数据，计算各区块生产者的动态评分；
3. 基于所述行为观测数据，计算各区块生产者的 reward 学习结果；
4. 基于所述动态评分和 reward 学习结果，计算各区块生产者的预期收益指标、健康度指标或综合优先级指标；
5. 识别样本不足、注册时间较短或观测数据不充分的区块生产者，并将其纳入 exploration 候选集合；
6. 当命中 exploration 条件时，基于预期收益、不确定性加权、样本不足补偿、新生产者奖励和/或 UCB bonus 计算探索分值，并依据探索分值选择目标区块生产者或输出探索评估结果；
7. 当未命中 exploration 条件时，基于动态评分和 reward 学习结果计算 exploitation 分值，并依据 exploitation 分值选择目标区块生产者或输出利用评估结果；
8. 根据后续反馈结果持续更新所述行为观测数据、动态评分和 reward 学习结果；
9. 输出区块生产者排序结果、健康评估结果、准入建议、风险预警结果或调度结果中的至少一种。

### 4.3 有益效果

与现有技术相比，本发明至少具有以下有益效果：

1. 通过面向区块生产者建立独立的动态评分机制，可以将长期信誉评估从具体业务链路中抽象出来，形成可复用的底层能力；
2. 通过 reward 学习结果反映区块生产者的近期状态变化，可提升对状态突变、行为恶化或收益波动的响应速度；
3. 通过 exploration / exploitation 分层机制，可在稳定利用成熟区块生产者与发现潜在优质新区块生产者之间取得平衡；
4. 通过对异常行为、风险行为和正向行为进行联合建模，可提升区块生产者健康评估的准确性与解释性；
5. 该机制不仅可用于具体的业务选择或策略路由，还可扩展用于健康评估、准入控制、风险预警和资源调度等场景。

## 5. 具体实施方式

### 5.1 系统组成

在一个实施例中，系统包括：

1. 数据采集模块，用于采集各区块生产者的行为观测数据；
2. 区块生产者画像模块，用于维护各区块生产者的行为统计、动态评分和历史状态；
3. reward 学习模块，用于根据行为观测结果生成近期收益质量信号；
4. 分层控制模块，用于基于 exploration 与 exploitation 机制对区块生产者进行评估、选择或调度；
5. 结果输出模块，用于输出区块生产者排序、健康评估、准入建议、风险预警或调度结果；
6. 指标记录模块，用于记录区块生产者画像快照、评分变化、reward 变化和分层决策结果。

### 5.2 行为观测数据实施方式

在一个实施例中，每个区块生产者对应一组行为观测数据，至少包括：

1. 服务尝试次数；
2. 服务成功次数；
3. 服务失败次数；
4. 异常行为次数；
5. 正向行为次数；
6. 价值产出累计值；
7. reward 样本数、累计 reward、平均 reward、最近 reward。

其中，异常行为可包括但不限于 sandwich attack、异常失效率上升、违规响应或其他风险模式；正向行为可包括但不限于稳定完成服务、持续高质量产出、符合预设规范的行为或其他可归因为健康信号的行为。

### 5.3 动态评分实施方式

在一个实施例中，系统基于所述行为观测数据，计算区块生产者的动态评分。动态评分用于表征区块生产者的长期信誉水平，可由以下因素共同确定：

1. 成功率对应的可靠性因子；
2. 连续失败对应的失败惩罚因子；
3. 异常行为对应的风险惩罚因子；
4. 正向行为对应的奖励因子；
5. 价值产出对应的价值奖励因子。

在一个具体实现中，区块生产者的有效分数可表示为：

`effective_score = base_score * reliability_factor * failure_factor * risk_factor * positive_factor * value_factor`

其中，risk_factor 随异常行为次数增加而下降，positive_factor 和 value_factor 随正向行为和价值产出增加而上升。

### 5.4 Reward 学习实施方式

在一个实施例中，reward 作为近期收益质量的学习信号，用于反映区块生产者近期表现是否优于或劣于其长期平均水平。所述 reward 可基于以下因素计算：

1. 服务成功率；
2. 失败率；
3. 价值产出；
4. 正向行为；
5. 异常行为惩罚。

在一个具体实现中，reward 可表示为：

`reward = success_weight * success_rate + value_weight * value_component + positive_weight * positive_component - failure_weight * failure_rate - risk_weight * abnormal_events`

基于 reward 样本累计得到 average_reward，并据此构建区块生产者的近期收益质量刻画。

### 5.5 动态评分与 Reward 的联合决策实施方式

在一个实施例中，系统并非仅依据动态评分或仅依据 reward 单独做评估决策，而是将两者联合使用。其中：

1. 动态评分反映区块生产者的长期信誉水平；
2. reward 反映区块生产者近期收益质量和状态变化；
3. 预期收益指标、健康度指标或综合优先级指标通过动态评分与 reward 组合得到，用于统一刻画区块生产者当前的综合状态。

在一个具体实现中，预期收益可表示为：

`expected_reward = reputation_score * reward_multiplier`

其中，reputation_score 来源于动态评分结果，reward_multiplier 来源于 reward 学习结果。

通过该联合建模方式，可以避免仅依赖长期历史均值导致对近期恶化响应过慢，也可以避免仅依赖短期 reward 导致评估结果波动过大。

### 5.6 Exploration / Exploitation 实施方式

在一个实施例中，系统将区块生产者分为成熟区块生产者与待探索区块生产者。若区块生产者满足以下任一条件，则可被认定为待探索区块生产者：

1. 样本数低于预设阈值；
2. 注册时间处于预设宽限期内；
3. 观测数据不充分或不确定性较高。

当系统命中 exploration 条件时，从待探索区块生产者集合中进行探索评估。探索分值可由下述因素组合得到：

1. 预期收益；
2. 样本不足补偿项；
3. 新生产者奖励项；
4. 不确定性权重项；
5. UCB bonus。

当系统未命中 exploration 条件，或者待探索区块生产者集合为空时，系统进入 exploitation 模式，基于 expected_reward 或综合优先级指标对成熟区块生产者进行利用评估。

通过上述设计，系统不再仅依赖历史优势区块生产者，而是能够在保持整体稳定性的同时，持续发现潜在高质量的新区块生产者，从而缓解长期中心化问题。

### 5.7 应用场景实施方式

在一个实施例中，本发明所述机制可独立应用于以下场景中的一种或多种：

1. 区块生产者健康评估；
2. 区块生产者准入控制；
3. 区块生产者风险预警；
4. 资源调度与策略排序；
5. 面向具体业务的区块生产者选择。

其中，面向具体业务的区块生产者选择仅是本发明的一个应用场景，而非对本发明的限定。

### 5.8 实验验证

在一个 mock 实验中，设置 7 个区块生产者并连续模拟约 10000 个目标区块，通过新区块事件为每个区块随机生成 0 至 5 个 bundle，并采用 exploration / exploitation 交替调度；实验产生 25618 个 bundle，其中 exploration 与 exploitation 各为 12809 次，平均每个目标区块约 2.52 个 bundle，alpha 初始评分为 85、最终为 97.16，订单流分发占比为 23.6%；其中一个初始评分为 85 的高分生产者在后半程持续产生 sandwich 行为，评分降至 19.12，另一恶意生产者评分降至 1.70；中途加入的 zeta 获得 3824 次分发，其中 2000 次为 exploration，结果表明所述动态评分与交替探索利用机制能够在保持高质量生产者优势的同时抑制流量集中，并降低恶意区块生产者的后续分发权重。

## 6. 权利要求

### 权利要求1

一种面向区块生产者的动态评分与探索利用自适应方法，其特征在于，包括：

获取多个区块生产者的行为观测数据；

基于所述行为观测数据，计算各区块生产者的动态评分和 reward 学习结果；

基于所述动态评分和 reward 学习结果，计算各区块生产者的预期收益指标或综合优先级指标；

根据样本充分性将区块生产者分为探索候选集合和利用候选集合，并分别进行探索评估和利用评估；

根据评估结果输出区块生产者排序、健康评估、准入建议或调度结果；

根据反馈结果持续更新所述行为观测数据、动态评分及 reward 学习结果。

### 权利要求2

根据权利要求1所述的方法，其特征在于，所述行为观测数据至少包括服务成功次数、服务失败次数、异常行为次数、正向行为次数和价值产出信息。

### 权利要求3

根据权利要求1所述的方法，其特征在于，所述动态评分由可靠性因子、失败惩罚因子、风险惩罚因子、正向奖励因子和价值奖励因子中的至少两项组合得到，用于表征区块生产者的长期信誉水平。

### 权利要求4

根据权利要求3所述的方法，其特征在于，当区块生产者产生异常行为时，动态评分的下降速度快于产生正向行为时的上升速度。

### 权利要求5

根据权利要求1所述的方法，其特征在于，所述 reward 学习结果基于服务成功率、失败率、价值产出、正向行为和异常行为惩罚计算，用于表征区块生产者的近期收益质量。

### 权利要求6

根据权利要求1所述的方法，其特征在于，所述预期收益指标由动态评分与 reward 学习结果联合计算得到，其中动态评分反映长期信誉水平，reward 学习结果反映近期收益质量。

### 权利要求7

根据权利要求1所述的方法，其特征在于，当区块生产者的样本数低于预设阈值或注册时间处于预设宽限期内时，将其纳入探索候选集合。

### 权利要求8

根据权利要求1所述的方法，其特征在于，探索评估的探索分值由预期收益、样本不足补偿项、新生产者奖励项和不确定性权重项中的至少一项组合得到。

### 权利要求9

根据权利要求1所述的方法，其特征在于，利用评估的利用分值包含竞争集中度惩罚，当区块生产者的流量份额高于预设阈值时，降低其利用分值。

### 权利要求10

一种面向区块生产者的动态评分与探索利用自适应系统，其特征在于，包括：数据采集模块、区块生产者画像模块、reward 学习模块、分层控制模块、结果输出模块和指标记录模块，所述系统实现权利要求1至9中任一项所述的方法。

### 权利要求11

一种电子装置，其特征在于，包括处理器和存储器，所述存储器中存储有计算机程序，所述计算机程序被所述处理器执行时实现权利要求1至9中任一项所述的方法。

### 权利要求12

一种计算机可读存储介质，其上存储有计算机程序，其特征在于，所述计算机程序被处理器执行时实现权利要求1至9中任一项所述的方法。

## 8. 具体实施方法（适用于专利正文）

本发明所述面向区块生产者的动态评分与探索利用自适应机制可通过以下方式实施。

在本申请实施例的一种实现方式中，系统整体由数据采集模块、区块生产者画像模块、reward学习模块、分层控制模块、结果输出模块和指标记录模块构成。

其中，数据采集模块用于采集各区块生产者的行为观测数据。

区块生产者画像模块用于维护各区块生产者的行为统计、动态评分和历史状态。

reward学习模块用于根据行为观测结果生成近期收益质量信号。

分层控制模块用于基于exploration与exploitation机制对区块生产者进行评估、选择或调度。

结果输出模块用于输出区块生产者排序、健康评估、准入建议、风险预警或调度结果。

指标记录模块用于记录区块生产者画像快照、评分变化、reward变化和分层决策结果。

### 一、数据采集模块的实施方式

在本申请实施例的一种实现方式中，系统运行时，首先通过数据采集模块获取各区块生产者的行为观测数据。

每个区块生产者对应一组行为观测数据，所述行为观测数据至少包括服务尝试次数、服务成功次数、服务失败次数、异常行为次数、正向行为次数、价值产出累计值、reward样本数、累计reward、平均reward以及最近reward等信息。

需要说明的是，异常行为是指区块生产者在服务过程中表现出的风险行为或违规行为。异常行为包括但不限于：sandwich attack行为、异常失效率上升、违规响应、超时响应以及其他可识别的风险模式。

相应地，正向行为是指区块生产者在服务过程中表现出的健康行为或优质行为。正向行为包括但不限于：稳定完成服务、持续高质量产出、符合预设规范的行为、响应及时以及其他可归因为健康信号的行为。

在实际应用中，价值产出信息可以包括但不限于：区块生产者为系统或用户创造的收益值、成功完成的订单价值、提取价值最大化（MEV）贡献值以及其他可量化的价值指标。

### 二、区块生产者画像模块的实施方式

在本申请实施例的一种实现方式中，系统基于所述行为观测数据，通过区块生产者画像模块计算各区块生产者的动态评分。

所述动态评分用于表征区块生产者的长期信誉水平。动态评分由成功率对应的可靠性因子、连续失败对应的失败惩罚因子、异常行为对应的风险惩罚因子、正向行为对应的奖励因子以及价值产出对应的价值奖励因子共同确定。

在一个具体实现中，区块生产者的有效分数可表示为：

```
effective_score = base_score × reliability_factor × failure_factor × risk_factor × positive_factor × value_factor
```

其中，base_score为基础分数；reliability_factor为可靠性因子，由服务成功率确定；failure_factor为失败惩罚因子，随连续失败次数增加而下降；risk_factor为风险惩罚因子，随异常行为次数增加而下降；positive_factor为正向奖励因子，随正向行为次数增加而上升；value_factor为价值奖励因子，随价值产出增加而上升。

需要说明的是，为避免评分偏离合理区间，所述动态评分按照百分制或归一化分值进行约束，并设置评分上限和最低有效分数。

在本申请实施例的一种实现方式中，当区块生产者产生正向行为时，系统以小于负向更新步长的正向更新步长使动态评分向正向目标分平滑上升。

相应地，当区块生产者产生异常行为或失败行为时，系统以负向更新步长使动态评分向负向目标分下降。

通过上述不对称更新机制，使异常行为造成的评分下降速度快于正常行为造成的评分上升速度，从而实现对高风险行为的快速抑制。

### 三、Reward学习模块的实施方式

在本申请实施例的一种实现方式中，系统在计算动态评分的同时，通过reward学习模块计算各区块生产者的reward学习结果。

所述reward作为近期收益质量的学习信号，用于反映区块生产者近期表现是否优于或劣于其长期平均水平。

所述reward可基于服务成功率、失败率、价值产出、正向行为和异常行为惩罚计算。在一个具体实现中，reward可表示为各因素的加权组合：

```
reward = success_weight × success_rate + value_weight × value_component + positive_weight × positive_component - failure_weight × failure_rate - risk_weight × abnormal_events
```

其中，success_weight为成功率权重；success_rate为服务成功率；value_weight为价值权重；value_component为价值产出归一化值；positive_weight为正向行为权重；positive_component为正向行为归一化值；failure_weight为失败率权重；failure_rate为服务失败率；risk_weight为风险事件权重；abnormal_events为异常行为归一化值。

在本申请实施例的一种实现方式中，系统根据多个reward样本累计得到平均reward，并据此构建区块生产者的近期收益质量刻画。

通过该机制，reward学习结果能够及时反映区块生产者近期状态的变化，所述变化包括但不限于：服务质量突变、行为恶化、收益波动以及其他可反映区块生产者近期状态异常的信号。

需要说明的是，系统并非仅依据动态评分或仅依据reward单独做评估决策，而是将两者联合使用。动态评分反映区块生产者的长期信誉水平，reward反映区块生产者近期收益质量和状态变化。

预期收益指标、健康度指标或综合优先级指标通过动态评分与reward组合得到，用于统一刻画区块生产者当前的综合状态。

在一个具体实现中，预期收益可表示为：

```
expected_reward = reputation_score × reward_multiplier
```

其中，reputation_score为声誉分数，来源于动态评分结果；reward_multiplier为reward倍数，来源于reward学习结果。

通过该联合建模方式，可以避免仅依赖长期历史均值导致对近期恶化响应过慢，也可以避免仅依赖短期reward导致评估结果波动过大，从而提升区块生产者健康评估的准确性和稳定性。

### 四、分层控制模块的实施方式

在本申请实施例的一种实现方式中，系统基于上述动态评分和reward学习结果，通过分层控制模块实施exploration与exploitation分层机制。

系统根据样本数、注册时间或观测数据充分性，将区块生产者分为成熟区块生产者与待探索区块生产者。

若区块生产者满足以下任一条件，则将该区块生产者纳入待探索区块生产者集合：样本数低于预设样本阈值；注册时间处于预设宽限期内；观测数据不充分；或不确定性高于预设不确定性阈值。

其中，预设样本阈值、预设宽限期和预设不确定性阈值可以根据实际需要设置，此处不作限制。

当系统命中exploration条件时，从待探索区块生产者集合中进行探索评估。所述exploration条件包括但不限于：触发探索概率、待探索区块生产者集合非空、当前区块处于探索周期内以及其他预设探索触发条件。

在本申请实施例的一种实现方式中，探索分值可由预期收益、样本不足补偿项、新生产者奖励项、不确定性权重项以及UCB bonus等因素组合得到。

其中，样本不足补偿项用于对样本数较少的区块生产者给予额外权重，避免因样本不足导致低估。

新生产者奖励项用于对注册时间较短的区块生产者给予初期扶持，促进新生产者的公平竞争机会。

不确定性权重项用于对观测数据不确定性较高的区块生产者给予探索激励，鼓励系统发现潜在优质区块生产者。

UCB bonus即置信上界奖励项，基于多臂老虎机理论中的UCB（Upper Confidence Bound）算法思想，为不确定性高的选项赋予探索价值。

系统根据探索分值对exploration候选区块生产者进行排序、筛选、准入评估或调度选择。

当系统未命中exploration条件，或者待探索区块生产者集合为空时，系统进入exploitation模式，基于预期收益或综合优先级指标对成熟区块生产者进行利用评估。

在本申请实施例的一种实现方式中，exploitation分值可由动态评分、reward学习结果、预期收益指标、健康度指标、历史成功率、风险惩罚、价值产出以及竞争集中度惩罚等因素组合得到。

其中，竞争集中度惩罚用于避免系统长期依赖少数既有区块生产者造成的中心化问题。当某一区块生产者的流量份额高于预设集中度阈值，或其相对收益低于预设收益阈值时，系统降低该区块生产者的exploitation分值，从而促进流量在多个高质量区块生产者之间的合理分配。

通过上述设计，系统不再仅依赖历史优势区块生产者，而是能够在保持整体稳定性的同时，持续发现潜在高质量的新区块生产者，从而缓解长期中心化问题。

### 五、结果输出模块的实施方式

在本申请实施例的一种实现方式中，系统通过结果输出模块输出区块生产者排序结果、健康评估结果、准入建议、风险预警结果或调度结果中的至少一种。

上述输出结果可独立应用于以下场景中的一种或多种：区块生产者健康评估、区块生产者准入控制、区块生产者风险预警、资源调度与策略排序、面向具体业务的区块生产者选择。

需要说明的是，面向具体业务的区块生产者选择仅是本发明的一个应用场景，而非对本发明的限定。

### 六、指标记录模块的实施方式

在本申请实施例的一种实现方式中，系统通过指标记录模块记录区块生产者画像快照、评分变化、reward变化和分层决策结果，从而支持历史溯源、效果分析和机制调优。

根据后续反馈结果，系统持续更新所述行为观测数据、动态评分及reward学习结果，实现在线学习和自适应调整，使区块生产者评估机制能够随着区块生产者行为的变化而动态演进。

### 七、实验验证

在一个mock实验中，设置7个区块生产者并连续模拟约10000个目标区块，通过新区块事件为每个区块随机生成0至5个bundle，并采用exploration与exploitation交替调度。

实验产生25618个bundle，其中exploration与exploitation各为12809次，平均每个目标区块约2.52个bundle。

实验中，初始评分为85的区块生产者alpha在稳定运行后评分上升至97.16，其订单流分发占比为23.6%。

其中一个初始评分为85的高分生产者在后半程持续产生sandwich行为，评分降至19.12。

另一恶意生产者评分降至1.70，表明系统对异常行为具有快速识别和持续惩罚能力。

中途加入的区块生产者zeta获得3824次分发，其中2000次为exploration分发，表明系统为新加入的区块生产者提供了充分的探索机会。

实验结果表明，所述动态评分与交替探索利用机制能够在保持高质量生产者优势的同时抑制流量集中，并降低恶意区块生产者的后续分发权重，从而验证了本发明所述机制在区块生产者管理中的有效性和适应性。
