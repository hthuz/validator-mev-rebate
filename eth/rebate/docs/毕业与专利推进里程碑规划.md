# 毕业与专利推进里程碑规划

> 起点：2026-10-07｜终点：2027-06（毕业）

## 0. 时间总览

| 里程碑 | 事项 | 起止时间 | 硬产出 | 状态 |
|---|---|---|---|---|
| M1 | 专利定稿与提交 | 2026.10.08 – 2026.11.15 | 说明书定稿 + 受理通知书 | ☐ |
| M2 | 实验补充与对比验证 | 2026.11.16 – 2026.12.31 | 实验报告 + 基线对比 + 图表 | ☐ |

**关键外部节点（务必以学院通知为准，提前 2 周对齐）：** 预答辩 → 学术不端检测（查重）→ 盲审送审 → 答辩 → 学位申请 → 离校。

## M1 专利定稿与提交（2026.10.08 – 11.15）

**对应产出**

1. 补全后的专利说明书定稿：在 `docs/patent_draft_producer.md` 基础上，并入 `docs/专利补充_应用场景与实施例_梳理.md` 里的**应用场景段 + 实施例 1/4/8 + 参数表**（或按篇幅取更多）。
2. 权利要求与说明书支持关系核对表（权 1–12 逐条 → 说明书对应段落）。
3. 全套附图（现有图 1–5：系统架构 / 联合决策 / 分层机制 / 现有技术问题 / 评分趋势）。
4. 代理机构提交回执 / 受理通知书（含申请号）。

**完成标准**

- [ ] 说明书含 **≥1 个应用场景段落 + ≥3 个实施例 + 1 张参数表**；
- [ ] 权利要求每条都能在说明书中找到支持，无"缺少必要技术特征"风险；
- [ ] 实施例中的公式与参数**前后一致**（统一引用参数表，不出现两套数字）；
- [ ] 已完成提交，取得**受理通知书 / 申请号**；
- [ ] 若可争取，同步提交**优先审查（快速预审）**请求。

**可执行任务清单**

- [ ] 把 `patent_draft_producer.md` 第 5 部分「具体实施方式」扩写为正式说明书体例（去掉 markdown 口语化表述）；
- [ ] 新增 `5.9 应用场景`（S1–S7，S8–S10 一段带过）；
- [ ] 新增 `5.10 具体实施例`（建议至少 实施例 1 动态评分 / 实施例 4 探索分值 / 实施例 8 端到端实验）；
- [ ] 权利要求第 4、9 条（"下降快于上升""集中度惩罚"）在实施例中给出可复现的数值算例；
- [ ] 附图 5 的评分类图用 `logs/experiment_mock_5builders/plots/builder_score_trends.png` 替换为高清版；
- [ ] 与代理机构过一遍 → 定稿 → 提交 → 归档受理通知书。

**风险**：代理机构若要求删减实施例篇幅，优先保留"端到端实验实施例"（它同时支撑多条权利要求）。

## M2 实验补充与对比验证（2026.11.16 – 12.31）

**对应产出**

1. **Replay 真实数据实验报告**：`simulator.mode: replay` + `data/ethereum_transactions.csv`，长周期跑通并出图（现有结论主要来自 mock 模式）。
2. **基线对比实验**：与固定权重 / 轮询 / 贪心 / ε-greedy 四类基线对比表。
3. 补充图表集：收益对比、score 收敛曲线、分发集中度、恶意生产者抑制曲线。
4. 一键复现脚本 + `metadata.json`（固定随机种子）。

**完成标准**

- [ ] mock 与 replay **两种模式**均有可引用结果，且结论一致；
- [ ] 与 **≥4 组基线**对比，主指标（总收益、分发集中度、恶意者占比、学习收敛速度）齐备；
- [ ] exploration/exploitation 两种模式（`alternating` / `probabilistic`）都有数据；
- [ ] 明确写出本机制的**相对增益**（如收益 +X%、集中度下降 Y%）；
- [ ] 脚本一键跑通、固定 seed、结果可复现。

**可执行任务清单**

- [ ] 新增 `config/experiment_replay_5builders.yaml`（`mode: replay`，`dataset_path: data/ethereum_transactions.csv`，缩小 `block_interval` 提高吞吐）；
- [ ] 跑 `scripts/run_mock_5builders_experiment.sh` 出 `alternating` 基线结果，再改配置跑 `probabilistic`；
- [ ] 在 `internal/builder/dispatcher.go` 的 `selectTarget` 旁挂一份**离线基线复算脚本**（用 `builder_dispatches.jsonl` 重放即可，不必改主链路）；
- [ ] 用 `scripts/plot_experiment_metrics.py` 统一出图，产出到 `logs/experiment*/plots/`；
- [ ] 补一组**"高分 producer 后期作恶"**与**"中途注册新 producer"**的对照实验（对应专利实施例 7、8）；
- [ ] 整理成 `docs/experiment_report_final.md`，直接作为论文实验章素材。

**风险**：replay 模式对真实交易模拟较慢，若吞吐不足，退化为"replay 抽样 + mock 长周期"组合，并在论文中说明。

## M5 毕业论文送审 & 答辩准备（2027.03 送审 – 2027.05 答辩）

**对应产出**

1. 送审（盲审）材料提交完成；
2. 盲审意见逐条回复表 + 修改说明；
3. 答辩 PPT（约 20 分钟）+ 讲稿 + 常见问题应答；
4. 答辩通过 + 学位申请材料。

**完成标准**

- [ ] **3 月内完成送审提交**，流程节点全部闭环；
- [ ] 盲审意见返回后 **1 周内**完成修改并出具逐条答复；
- [ ] 答辩 PPT 完成预答辩演练，**预答辩通过**；
- [ ] 答辩现场通过，答辩委员会无重大异议；
- [ ] 学位申请材料（申请表、成绩单、成果清单、专利受理通知书等）齐全提交。

**可执行任务清单**

- [ ] 3 月：提交盲审 → 跟踪意见 → 收到后 1 周内完成修改答复；
- [ ] 3–4 月：做答辩 PPT 骨架（选题背景 / 问题 / 方法 / 系统 / 实验 / 结论），可参考 `docs/image.pptx` 视觉模板；
- [ ] 准备"创新点"3 句话版本，能对着非本方向老师讲清；
- [ ] 预演 2 次并计时，压到 18–20 分钟；
- [ ] 预习高频提问：与 MEV-Boost 的关系、探索成本、参数敏感性、为何用 UCB、安全性/博弈；
- [ ] 答辩通过后：提交最终归档版论文（含签字页扫描）。

## 一句话执行原则

**M1 抢在 11 月前交掉专利 → M2 用 12 月把实验数据打厚 → M3/M4 用 1–2 月把论文做扎实 → M5 只做送审答辩，不再动内容。**
每完成一个里程碑，回填上表"状态"列并核对"完成标准"是否全部勾选，未达标不进入下一阶段。
