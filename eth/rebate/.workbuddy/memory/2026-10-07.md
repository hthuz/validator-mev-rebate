## 专利补充梳理：应用场景与实施例

- 产出：`docs/专利补充_应用场景与实施例_梳理.md`
- 背景：专利《一种面向区块生产者的动态评分与探索利用自适应机制…》正文（PDF = `docs/patent_draft_producer.md`）缺「具体应用场景」与「实施例」两段。
- 做法：从代码反推可写入说明书的真实技术细节——
  - 评分/奖励实现见 `internal/builder/registry.go`（effective_score 因子链、reward 权重、竞争集中度惩罚、非对称平滑 0.01/0.05）。
  - 分层与 UCB 见 `internal/builder/dispatcher.go`（explorationWeight / banditScore / alternating 与 probabilistic）。
  - 配置项见 `config/config.go` 的 `StrategyConfig` 与 `config/experiment_5builders.yaml`。
  - 运行接口：`GET /builders/scores`、`POST /builders/register`、`POST /builders/observe`（`internal/builder/http_handler.go`、`cmd/server/main.go`）。
  - 实验数据见 `docs/experiment_mock_10000blocks.md`（25618 次分发，exploration:exploitation = 12809:12809，各 builder 最终 score）。
- 文档结构：0 现状缺口 → 1 应用场景 S1–S7(+S8–S10 扩展) → 2 实施例 1–9（技术细节/如何操作/预期效果三段式）→ 3 参数表 → 4 最小补充清单。
- 关键结论：建议最少补 1 段应用场景 + 3 个实施例（动态评分 / 探索分值 / 端到端实验）+ 1 张参数表。
