# 2026-11-19

## 公共层：block JSON -> BlockTransaction 加载器

按 CLAUDE.md 分层，不改已有 `Transaction`（mitigation 的用户提交交易），新增独立类型。

- `type/models.py` + `type/__init__.py`：新增 `BlockTransaction` dataclass，字段严格只保留
  `signatures / message / fee / preBalances / postBalances / instructions / logMessages / timestamp`，
  再加区块 `slot`。`signature` property 取第一笔签名。
- `utils/utils.py` + `utils/__init__.py`：新增
  - `parse_block_transactions(block_data, slot=None)`：兼容 RPC 外壳 `result.transactions` 与裸结构；
    slot 优先级 显式参数 > JSON 内 slot > 抛 ValueError。
  - `load_block_transactions(block_file, slot=None)`：从文件加载，slot 默认从文件名解析
    （`block_346769956.json` -> 346769956）。
  - 注意 `type.validator` 反向 import `utils`，所以 `BlockTransaction` 在加载函数里**延迟导入**，
    不要在 utils 模块级 import type，否则循环依赖。
- `scripts/load_block_transactions.py`：示例脚本（脚本直接运行时要 sys.path.insert 项目根目录）。
  默认跑 `ref/block_346769956.json`，1734 笔交易，第一笔是 vote 交易，fee=5000。
- `tests/test_block_tx_loader.py`：7 个测试，覆盖两种 JSON 结构、字段白名单、slot 三种来源、真实 ref 样例。

验证：`pytest tests/ mitigation/tests/` -> 18 passed（唯一 warning 是原有 test_imports 返回 bool）。

备注：JSON 是 jsonParsed 编码（accountKeys 是 dict、instructions 带 parsed 字段）；
Go 版 collector.go 是 base64 编码，字段语义一致但编码不同。
mitigation/user/client.py 目前仍按裸 `block_data.get('transactions')` 取数，与 ref 的 RPC 外壳不匹配，
本次未改动（用户只要求公共层 loader）；后续接入时改用 `load_block_transactions` 即可。

## RiskAwareStrategy 打通（历史 epoch ratio 跳过高风险 leader）

- 需求确认：server 维护历史 epoch（config 限定 800-801）各 validator 的 sandwich ratio；
  任一 epoch ratio > 阈值（默认 0.5）即高风险；当前 leader 高风险则持有交易直到遇到安全 leader，
  达到最大窗口（默认 10 slot）强制发送；质押维度暂不做。
- `config/settings.py` + `__init__.py` + `.env.example`：新增 SANDWICH_HISTORY_START_EPOCH/END_EPOCH、
  SANDWICH_RATIO_THRESHOLD、MITIGATION_MAX_SKIP_SLOTS。
- `utils/sandwich.py`：新增 `get_sandwich_ratios(epoch)`，复用 `SlotInfo.sandwich_ratio()`。
  注意用户已自行把底部 demo 改成 `if __name__ == "__main__"` 跑 epoch 801 并排序 top100，
  编辑该文件前必须先重读，不能按旧内容整文件覆盖。
- `mitigation/risk_store.py`（新）：`ValidatorRiskStore` 按 epoch 范围加载 ratio，
  `is_risky()` 任一 epoch 严格超阈值即 True；NaN/缺失视为安全；loader 可注入便于测试。
- `mitigation/strategy/base_strategy.py`：新增 `StrategyContext`（get_leader + risk_store），
  `send_to_validator(..., current_slot)` 写入 target_slot/delay_slots/leader_risky。
- `mitigation/strategy/risk_aware_strategy.py`（新）：跳过 / 达到窗口强制发送；无 context 时退化为 immediate。
- `type/models.py`：`TransactionRecord` 新增 target_slot / delay_slots / leader_risky（带默认值，向后兼容）。
- `mitigation/server.py`：注入 context；仅 risk-aware 策略才构造 risk store（避免其他模式连 ClickHouse）；
  新增 `/risk/summary`；`/transactions/sent` 输出新字段。
- `mitigation/scripts/run.py`：`--strategy risk-aware`，`--max-skip` / `--threshold` 覆盖配置。
- `mitigation/tests/test_risk_aware.py`（新）6 个测试；`mitigation/README.md` 更新。

验证：`uv run python -m pytest tests/ mitigation/tests/ -q` -> 35 passed。
