# 2026-11-18

## mitigation slot 机制重构（事件驱动）

按 hthuz 要求把 mitigation 模块的 slot 机制从「定时器推进」改为「事件驱动」：

- **slot 统一为 slot start time**：即区块 JSON 的 `blockTime`（Unix 秒）。同一秒内的多个真实区块归为同一个模拟 slot（真实数据 2533 个 block → 1021 个 start time）。
- **链路**：server 进入新 slot → Socket.IO 广播 `new_slot {slot, leader}` → user 从 `BLOCKS_DATA` 取该 slot 交易逐笔 POST → server 按策略处理（immediate 收到即发验证者）→ user 发 `{"slot": ..., "end": true}` → server 处理收尾、推进 slot、再广播。无 sleep 定时器。
- **广播用 Socket.IO**：项目 pyproject 里 uncommitted 新增的 flask-socketio / python-socketio 依赖就是为此准备的。user 端用 python-socketio Client（websocket-client 未装，走 polling，可用）。

改动文件：
- `utils/utils.py` + `utils/__init__.py`：新增 `build_block_time_index()`（只读文件头 512B 提取 blockTime，避免解析 16GB 数据）、`extract_slot_from_block_path()`。
- `mitigation/slot_manager.py`：重写为 start time 索引 + leader 映射，新增 `reset_to_first_slot()` / `has_next_slot()`。
- `mitigation/transaction_manager.py`：新增 end 标识跟踪与按 id 部分移除（延迟策略用）。
- `mitigation/server.py`：Flask-SocketIO，删除 slot 推进线程/键盘监听/400ms sleep；`/sendTransaction` 支持 `end` 字段；新增 `simulation_done` 事件。
- `mitigation/user/client.py`：广播驱动 + BLOCKS_DATA 按需加载；删除独立 timer 的 `run_simulation()`。
- `mitigation/tests/test_slot_protocol.py`（新增）、`mitigation/README.md`、`mitigation/user/client_example.py`。

验证：合成数据 E2E 通过（3 个 slot × 2 笔交易，全部即时发给正确 validator，end 后才推进）；`pytest mitigation/tests/` 9 passed。

注意：服务端 `start()` 里 socketio.run 用了 `allow_unsafe_werkzeug=True`（开发服务器）。
